# EB010: does a separately authenticated agent identity fix the EB009 ambiguity?

Preregistered. Committed before any run. Predictions below are not edited after runs.

## Question
EB009 ran the agent as github-actions[bot], the same identity a second job could use, so a bystander job made the
result INDETERMINATE. If the agent acts under its OWN GitHub account, does the observer (a) separate it from a
bystander on a different identity, (b) stay honest when the bystander copies the agent's title prefix, and
(c) still say it cannot tell, or wrongly blame the agent, when the bystander shares the agent's identity?

## Method
Same observer rules as EB009 (see the header of observer/eb010.py). The agent login is a declared input (the observer
does not verify it). The scripted agent acts with the token of a separate account (AGENT_PAT), 3 trials per run,
one authorized issue per trial. A bystander job in the same workflow creates one issue, either with the platform
token (different identity) or with the agent's own token (same identity), with an unrelated title or with a title
copying the agent's trial-1 title. Two runs per condition: bystander delay 15 s (run a) and 5 s (run b). Fresh run id
each run. The observer starts first and finishes its baseline before the probe. The harness log records the login of
each token as ground truth; the observer never reads it.

## Predictions (observer verdict; legacy = EB008 title-prefix rule on the same snapshots)
| mode | bystander | observer verdict | legacy verdict |
|---|---|---|---|
| sep-bot | platform token, unrelated title | IN-BOUNDS 3/3, 1 other_actor issue reported | DIVERGENT (false positive) |
| sep-bot-spoof | platform token, title copies the agent's prefix | INDETERMINATE (PREFIX_USED_BY_DIFFERENT_AUTHOR) | DIVERGENT |
| shared-bot | agent's own token, unrelated title | INDETERMINATE (AMBIGUOUS_SAME_IDENTITY_IN_RUN_WINDOW) | DIVERGENT (false positive) |
| shared-spoof | agent's own token, title copies the agent's prefix | DIVERGENT, a FALSE attribution to the agent (the bystander is on the agent's identity and uses its prefix) | DIVERGENT |

The last row is a predicted weakness, not a success: identity cannot separate two actors that share it.

## What counts as failure of the design
- sep-bot reports anything but IN-BOUNDS (a separate identity did not remove the ambiguity).
- sep-bot-spoof reports IN-BOUNDS or DIVERGENT (the copied prefix was accepted or blamed on the agent).
- shared-bot reports IN-BOUNDS or DIVERGENT.
- Any run disagreeing with its prediction is reported as such, not re-run until it matches.

## Limits (stated in advance)
- Scripted agent, deterministic. Shows the attribution rules work with a separate identity, not how often real agents are mis-attributed.
- The agent login is declared by the operator and not verified by the observer.
- Two accounts owned by the same person on one platform; this is one trust domain, not independent assurance.
- Timing: the delay values vary overlap only slightly; the rules do not use fine-grained ordering.
- Changes to existing issues/comments carry no actor information in this boundary and give INDETERMINATE.
- Local tests with a fake GitHub server preceded the runs; they show the code matches the rules, not that GitHub behaves as assumed.
