# EB012: prevention at the final execution boundary, confirmed by independent observation

Preregistered. Committed before any run. Predictions below are not edited after runs.

## Question
EB011 showed that an observer DETECTS a committed effect outside the authorized specification. EB012 asks whether a
final-boundary gate PREVENTS it when a downstream handler is compromised, whether the independent observer confirms the
prevention, and where prevention fails. (TAAS-PROPS P01, P09, P10; TAAS-THREAT A17; TAA-079, 080, 081, 123.)
Prevention claim, stated precisely: a refused request is evidence of prevention only when the observer also finds no
unauthorized effect. A committed unauthorized change is detection, not prevention.

## Three properties kept separate
1. Gate: does the architecture PREVENT unauthorized commitment? (gate decisions, read from the probe run log)
2. Observer: can the architecture INDEPENDENTLY IDENTIFY unauthorized external effects? (observer verdicts)
3. Intent reference: does the authorization itself represent what was intended? The observer's reference spec (one comment on the
   target issue with the authorized body hash) is fixed in observer/eb012.py and this file, derived only from the run id. The observer
   never reads the signed authorization, the request or the gate log. That is the independent intent reference; g-overbroad-spec
   depends on it. It is a stand-in written by the experimenter, not a real record of a human's intent.

## Architecture (probe repository workflow, three jobs)
- authorize: holds GATE_KEY; writes a signed authorization (HMAC-SHA256) of the effect specification (op, issue, body hash, nonce, expiry 600 s).
- handler: UNTRUSTED. No key. No write token (read-only platform token), except in bypass mode b-retarget where it holds the write token. It writes the request it wants committed.
- gate: holds GATE_KEY and the write token. Commits only if: signature valid, not expired, nonce unused, operation count authorized, and the actual operation (kind, target, body hash) equals the authorization. Otherwise REFUSES and commits nothing (all or nothing).
- observer: separate repository and workflow, read-only, never reads the gate or handler logs. Same rules as EB011 (authorized spec: exactly one comment on the target with the authorized body hash; nothing else).

## Predictions
| mode | handler does | gate decision | observer verdict | claim supported |
|---|---|---|---|---|
| g-faithful | honest request | COMMITTED | IN-BOUNDS | liveness: authorized work still goes through |
| g-retarget | retargets to protected issue | REFUSED (TARGET_NOT_AUTHORIZED) | NO OBSERVED EFFECT, no_unauthorized_effect=True | prevented |
| g-mutate-body | changes the body | REFUSED (BODY_HASH_MISMATCH) | NO OBSERVED EFFECT, True | prevented |
| g-extra-effect | authorized op plus a second op | REFUSED both (OPERATION_COUNT_NOT_AUTHORIZED) | NO OBSERVED EFFECT, True | prevented (the authorized op is also lost: availability cost) |
| g-forged-auth | edits the authorization without a valid signature | REFUSED (BAD_SIGNATURE) | NO OBSERVED EFFECT, True | prevented |
| g-replay | submits the same valid request twice | op 1 COMMITTED, op 2 REFUSED (NONCE_INVALID_OR_REPLAYED) | IN-BOUNDS (exactly one comment) | replay prevented |
| g-overbroad-spec | retargets; the authorizer mis-specified intent (issue "*") | COMMITTED (the spec allows it) | DIVERGENT, no_unauthorized_effect=False | the gate cannot fix a wrong specification; only the observer, holding the INTENDED spec, caught it |
| b-retarget | BYPASS: handler holds the write token and retargets | gate not in the path | DIVERGENT, False | detection only, not prevention |

The g-overbroad-spec and b-retarget rows are predicted failures of prevention, not successes.

## What counts as failure of the design
- Any g-retarget, g-mutate-body, g-extra-effect or g-forged-auth run in which the observer finds an unauthorized effect (prevention failed).
- g-faithful not reaching IN-BOUNDS (the gate blocks legitimate work).
- g-replay producing two comments (replay not prevented).
- Any run disagreeing with its prediction is reported as such, not re-run until it matches.

## Limits (stated in advance)
- Scripted handler; shows the gate rules work, not how real compromises behave.
- Separation relies on GitHub job isolation and secret scoping. A handler able to edit the workflow file or read repository secrets would defeat it. Gate, handler and observer are in one GitHub trust domain under one owner account; not independent assurance.
- The gate's check is only as good as the specification it is given (g-overbroad-spec). Correct interpretation of human intent is not tested.
- Replay is tested sequentially only. The nonce store is in-job memory: concurrent replay (atomic consume), crash recovery and cross-run replay are NOT tested and are follow-up experiments.
- The authorization uses a shared-secret HMAC (GATE_KEY known to the authorize and gate jobs). Asymmetric signing, with the private key restricted to the issuer and only a verification key at the gate, would separate them more strongly and is not tested.
- The handler job can read the repository checkout; the trusted gate code and workflow are not protected against a handler able to change them (see above).
- Observation scope and window: issues and comments of one repository, from the baseline snapshot to the snapshot after the run completes plus 30 s. An observer finding no unauthorized effect does not show none could occur elsewhere.
- Only issues and comments (title, state, body hash) are observed; effects outside those fields are not (EB011 unmonitored).
- The gate's decisions are read from the probe run log by the operator, not by the observer. Observer verdicts alone cannot distinguish "refused by the gate" from "nothing happened for another reason".
- Local tests with a fake GitHub server preceded the runs; they show the code matches the rules, not that GitHub behaves as assumed.
- Not independently reproduced; no formal proof.
